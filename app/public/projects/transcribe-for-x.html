Personal project · Engineering case study

Transcribe-for-X

From a spoken thought to words the speaker controls.

I wanted to speak an unfinished thought and keep ownership of the final wording. That meant preserving the recording and making recognition, cleanup, and editing separate steps.

  • Android / Java
  • Local ASR
  • Data integrity

The speaker's problem

An unfinished thought can contain fillers, repetitions, and self-corrections. Recognition may get words wrong, while an aggressive cleanup can erase something the speaker meant to keep.

Transcribe-for-X keeps a path back to SourceAudio, presents RawTranscript separately from cleanup suggestions, and leaves the final wording with the user. Its current implementation is an Android Voice-to-Words foundation with local recognition.

  1. 01Record
  2. 02Save & verify
  3. 03Local ASR
  4. 04Approve cleanup
  5. 05Edit & copy

The choice I made

I put verified storage before recognition. SourceRepository checks capture evidence, syncs and saves the recording, reads it back, compares size and SHA-256, and records a manifest. AsrGateway must resolve a verified source before invoking the local NativeWhisper engine.

I also kept cleanup conservative: TranscriptCleanup proposes removals, the user accepts or rejects them individually, and the projection is checked to remove only accepted spans. This adds storage, failure handling, and review work, while keeping the source and the speaker's decisions visible.

What it produces today

The Android implementation connects recording and verified source storage to local ASR, per-suggestion cleanup, editable final text, and an explicit Copy action. That gives the project a concrete product path, with raw recognition and user-approved changes kept distinct.

The current result is an implemented Android path. Mixed Traditional Chinese/English recognition quality, microphone behavior, recovery, and private real-use acceptance still need separate evidence.

Transcribe-for-X

把口述想法變成作者仍能掌握的文字。

我希望能說出未成形的想法，也保有最後措辭的決定權。因此，錄音需要留下來，辨識、cleanup 與編輯也要各自清楚。

  • Local ASR

說話者的問題

未成形的想法可能包含語助詞、重複與自我修正。辨識可能聽錯，而過度的 cleanup 也可能刪掉說話者原本想保留的意思。

Transcribe-for-X 保留追回 SourceAudio 的路徑，分開呈現 RawTranscript 與 cleanup suggestions，讓使用者決定最後措辭。目前實作是以本機辨識為核心的 Android Voice-to-Words foundation。

  2. 02保存與驗證
  3. 03Local ASR
  4. 04核准 cleanup

我的關鍵選擇

我把 verified storage 放在辨識之前。SourceRepository 檢查 capture evidence、sync 並保存錄音，再讀回比對大小與 SHA-256，最後記錄 manifest。AsrGateway 必須先 resolve verified source，才能呼叫本機 NativeWhisper engine。

Cleanup 也採保守路徑：TranscriptCleanup 提出 removal suggestions，使用者逐項接受或拒絕，projection 再檢查只移除已接受的 spans。這增加儲存、失敗處理與 review 工作，也讓來源和說話者的決定維持可見。

目前可看見的結果

Android 實作已把錄音與 verified source storage 接到本機 ASR、逐項 cleanup、可編輯的 final text 與明確 Copy 動作。專案已有具體的產品路徑，原始辨識結果和使用者核准的改動維持分開。

目前成果是一條已實作的 Android 路徑。正體中文／English 混合語音品質、microphone 行為、recovery 與私密 real-use acceptance，仍需要各自的證據。
